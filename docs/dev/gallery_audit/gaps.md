# Gallery gaps — root cause analysis

Date: 2026-05-17

## Summary

The Sphinx-Gallery configuration in `/Users/suchethacooray/Projects/tengri/docs/conf.py` implements a smart caching strategy where scripts are skipped on re-builds if their main output PNG is already committed. However, three distinct gaps emerged:

1. **astrodust_hd23/**: All 8 scripts render to thumbnails but NOT main PNGs — missing from commits entirely
2. **Seven dust scripts**: Scheduled to execute (not in skip list) but main PNGs never committed; only .zip archives exist
3. **recipes / usecases / workflows**: Directories lack README files, so sphinx-gallery never generates per-section index.rst files

## 1. astrodust_hd23 — 0/8 main PNGs + 8/8 thumbnails

### Root cause

The 8 astrodust scripts (`plot_01_size_distribution.py` through `plot_08_polarized_emission.py`) execute successfully and **do** generate thumbnails (committed 2026-05-09 in `docs/auto_examples/astrodust_hd23/images/thumb/`). However, **the main full-size PNG images were never committed**, only the thumbnails.

The scripts are NOT in the _DO_NOT_EXECUTE skip list because no main PNG `sphx_glr_plot_0X_*_001.png` exists in committed state.

### conf.py implications

Lines 67–81 in `docs/conf.py`:
```python
_DO_NOT_EXECUTE = sorted(
    {
        p.stem.replace("sphx_glr_", "").rsplit("_", 1)[0]

    ...
    "filename_pattern": rf"^(?!.*({_skip_alt}))plot_.+\.py$",

```

**The 8 astrodust scripts are NOT in _DO_NOT_EXECUTE** because the glob `*/images/sphx_glr_plot_0*_001.png` matches 0 main PNGs. Therefore, they are scheduled to **execute every build** if `plot_gallery=True` (line 91: `"plot_gallery": "False" if os.environ.get("CI", "").lower() == "true" else "True"`).

### Remediation

**Option A: Commit the main PNGs** (preferred for fast CI builds)
1. Run `make html` locally with JAX cache warm (or re-warm with `TENGRI_JAX_CACHE_DIR=~/.cache/tengri_jax_cache make html`).
2. Verify main PNGs generated in `docs/auto_examples/astrodust_hd23/images/`:
   ```
   sphx_glr_plot_01_size_distribution_001.png
   ... (all 8)
   ```
3. Commit all 8 main PNGs plus the updated `docs/auto_examples/astrodust_hd23/index.rst`:
   ```
   git add docs/auto_examples/astrodust_hd23/images/sphx_glr_plot_*.png
   git add docs/auto_examples/astrodust_hd23/index.rst
   git commit -m "docs(astrodust_hd23): commit auto-generated main PNGs"
   ```
4. After commit, next `make html` will detect 8 main PNGs via glob and add all 8 basenames to _DO_NOT_EXECUTE, skipping re-execution on subsequent builds.

**Option B: Exclude astrodust_hd23 from execution** (if data is too large or compiles are too slow)
Modify conf.py line 75 to explicitly exclude these scripts:
```python

```
This removes them from the gallery entirely, which is appropriate if they're tutorial-only and not meant to regenerate.

## 3. recipes / usecases / workflows orphaned from index

### Root cause

The directories `examples/recipes/`, `examples/usecases/`, and `examples/workflows/` each contain 6–7 python scripts but **lack README.rst (or README.md) files**. Sphinx-Gallery requires a README in each gallery section to generate an `index.rst` file.

### Evidence

**Scripts exist:** 19 total across the three directories.
```bash

ls examples/workflows/*.py      # 6 files
```

**Missing README files:**


**Auto-generated index.rst files:**

**Images directory (with thumbnails):**

```bash
ls docs/auto_examples/usecases/images/thumb/*.png       # Files exist, but no index
```

**Contrast with sections that DO have README + index.rst:**

```
examples/dust/README.rst            → docs/auto_examples/dust/index.rst ✓
examples/astrodust_hd23/README.rst  → docs/auto_examples/astrodust_hd23/index.rst ✓
... (16 other sections) ...
```

All 16 sections with committed README files have corresponding auto-generated index.rst in the docs.

**Top-level index.rst toctree:**
The `docs/auto_examples/index.rst` (lines ~2–17 in the toctree, processed by _fix_gallery_index_toctree at line 99) includes:
```rst
/auto_examples/advanced/index.rst
/auto_examples/agn/index.rst
...
/auto_examples/xray/index.rst
```

**BUT NOT:**
```
/auto_examples/recipes/index.rst
/auto_examples/usecases/index.rst
/auto_examples/workflows/index.rst
```

So even if index.rst files were generated, they would not be listed in the toctree.

### Sphinx-Gallery behavior

From sphinx-gallery documentation and code, the generator scans `examples_dirs` (line 68: `["../examples"]`) and:
1. For each subdirectory (e.g., `examples/dust/`), looks for a README.{rst,md} file.
2. If found, generates `gallery_dirs/<section>/index.rst` based on the README + discovered .py scripts.
3. If NOT found, the section is **skipped entirely** — no index, no toctree entry, no gallery listing.

**Code reference:** `docs/conf.py` lines 67–69:
```python
sphinx_gallery_conf = {
    "examples_dirs": ["../examples"],
    "gallery_dirs": ["auto_examples"],
```

The default sphinx-gallery behavior is to require a README per section.

### conf.py post-processor logic

Lines 99–127 define `_fix_gallery_index_toctree()`, which runs after sphinx-gallery generates `auto_examples/index.rst`. It:
1. Extracts the toctree block from the bottom of the generated file.
2. Moves it to the top (after `:orphan:`).

This post-processor does NOT add missing sections; it only moves an existing toctree. Missing READMEs mean sphinx-gallery never creates the index.rst, so there's nothing to move.

### Remediation

**Create a minimal README for each section** (recommended; takes ~5 min):

1. **examples/recipes/README.rst:**
```rst
Recipes
=======

Curated model-building workflows — combining physics components and observational constraints for specific science goals.
```

2. **examples/usecases/README.rst:**
```rst
Use Cases
=========

End-to-end figures and analyses from real data — age-dust degeneracy resolution, high-z LBG SED fitting, emission-line diagnostics, and post-starburst identification.
```

3. **examples/workflows/README.rst:**
```rst
Workflows
=========

Advanced fitting strategies — Bayesian model comparison, dust resampling for Monte Carlo, BPT classification of AGN, and method validation.
```

After adding these files, the next `make html` will:
1. Generate `docs/auto_examples/recipes/index.rst`
2. Generate `docs/auto_examples/usecases/index.rst`
3. Generate `docs/auto_examples/workflows/index.rst`
4. Append a toctree block (moved to top by `_fix_gallery_index_toctree`)

**Result:** The sections will appear in the sidebar and be browsable in the HTML docs.

## Cross-cutting recommendations

### 1. Commit strategy for heavy templates

The current design (lines 51–63) is sound: **commit the outputs, skip re-execution**. However, it's applied inconsistently:

- **astrodust_hd23, bosa_*, pahspec_*:** Never committed main PNGs → every `make html` re-executes all of them.
- **Other 131 scripts:** Committed → skipped on rebuild (fast CI).

**Action:** Make a single commit that includes all missing PNGs (see **Option A** above for both gaps 1 and 2). This is a one-time cost (~GB of binary files, but compressible in git-lfs if size is a concern) that pays off in fast CI thereafter.

### 2. Thumbnails are not sufficient

The code at lines 67–81 only checks for **main PNGs** (`_001.png`), not thumbnails. This is correct for deciding whether to re-execute (thumbnails are auto-generated by sphinx-gallery as a smaller version of the main image). However, it created confusion here:

- astrodust_hd23 was partially committed (thumbs only) on 2026-05-09, giving a false impression of completeness.
- On the next rebuild, no main PNGs existed, so all 8 were re-executed.

**Action:** Document this in a code comment or changelog: "sphinx-gallery auto-generates thumbnails from main PNGs; committing only thumbs is incomplete."

### 3. Enforce README requirement in CI

To prevent future orphaned sections like recipes/usecases/workflows:

**Add a CI check:**
```python
# In conf.py or as a standalone pre-build script
import sys
from pathlib import Path

missing_readmes = []
for section_dir in Path("examples").iterdir():
    if section_dir.is_dir() and not section_dir.name.startswith("_"):
        if not (section_dir / "README.rst").exists() and \
           not (section_dir / "README.md").exists():
            missing_readmes.append(section_dir.name)

if missing_readmes:
    print(f"ERROR: Missing README in {missing_readmes}")
    sys.exit(1)
```

Run this before `make html` in CI. Catches missing READMEs early.

### 4. Document the _DO_NOT_EXECUTE policy

The glob-based skip list is elegant but opaque. Add a docstring to conf.py around lines 51–63:

```python
# ── Skip-execution list, derived from what is already pre-rendered ─────────
# Policy: do NOT re-execute any script whose main figure
# ``docs/auto_examples/<group>/images/sphx_glr_<name>_001.png`` is already
# committed. If the image is missing, the script will execute on the next
# ``make html`` and produce one. So the contract is "fetch the current ones,
# only reproduce if missing" — driven by what's on disk, not a hand-curated
# list. Heavy inference scripts stay fast because their pre-rendered output
# is committed; lightweight new scripts auto-rebuild on first build.
#
# Ensure all main PNGs are committed after running `make html` locally.
# (Thumbnails auto-regenerate; only check for main PNGs with _001.png suffix.)
```

This is already present in the current code; ensure it stays in all future refactors.

### 5. Consider git-lfs for large binary outputs

If committed PNGs exceed ~100 MB total, consider git-lfs:
```bash
git lfs track "docs/auto_examples/**/images/*.png"
```

This keeps the git history lean while preserving binary fidelity.
