### Task T1: migrate the notebooks off `Fitter(...).run(...)`

**Executor:** haiku (one dispatch per notebook — small blast radius, easy review)
**Branch:** `docs/notebooks-final-path` (single branch; commits per notebook)

**Files:** the ~12 call sites found by:

```bash
rg -n "Fitter\(" notebooks/*.py
```

(The historical count is 12 across `00_quickstart.py`, `01_why_jax.py`, `05_fitting_photometry.py`, `11_catalog_fits.py`, and others — the `rg` output at execution time is the source of truth; paste it in the task report.)

**Per-notebook procedure (repeat for each file):**

- [ ] **Step 1: Rewrite the call site** using the taught path. The three patterns:

```python
# BEFORE                                            # AFTER
fitter = Fitter(fwd, flux, noise,                   post = fwd.fit(flux, noise,
                data_type="photometry")                            method="mcmc_nuts",
post = fitter.run(method="mcmc_nuts", key=k, ...)                  key=k, ...)

# one-liner variant (01_why_jax.py style)
post = Fitter(model, flux, noise).run(...)          post = model.fit(flux, noise, ...)   # sed.fit sugar

# catalog notebook (11_catalog_fits.py)
cp = CatalogFitter(model, galaxies).run(key=k, **KW)
                                                    cat  = Catalog(fwd, table, flux_unit="cgs_fnu", ...)
                                                    cp   = cat.fit(key=k, **KW)
```

Keep every hyperparameter (`n_warmup`, `n_samples`, chains, chunk sizes) numerically identical — this wave changes the *spelling*, never the fit. Where the notebook built a bare `SEDModel` and used `Fitter(sed, …)`, prefer `sed.fit(...)` (the astronomer voice); where it built a `ForwardModel`, use `fwd.fit(...)`.

- [ ] **Step 2: Prose pass** on the surrounding markdown cells: the sentence introducing the fit must name the object actually used ("we call `model.fit`…"), in astronomer voice (`feedback_astronomer_voice_in_notebooks`). No references to `Fitter` remain in prose.
- [ ] **Step 3: Verify, tiered by cost.**
  - All notebooks: `python -m py_compile notebooks/<file>.py` and `rg -n "Fitter\(" notebooks/<file>.py` returns nothing.
  - Cheap notebooks only (no NUTS, or NUTS with ≤ 300 warmup on D ≤ 7): execute serially `JAX_PLATFORMS=cpu .venv/bin/python notebooks/<file>.py` with the OOM watchdog running; paste the tail of stdout.
  - Known-heavy notebooks (`rg -l "dense_basis|n_warmup=6|PopulationFitter" notebooks/`): do NOT execute; mark "compile-checked only — executes in the scheduled notebook CI" in the report.
- [ ] **Step 4: Sync + commit per notebook:** `cd notebooks && jupytext --sync <file>.py`; `git commit -m "docs(notebooks): <file> teaches forward.fit/sed.fit, not Fitter"`.

**Orchestrator review:** diff shows only call-site + prose changes; hyperparameters bit-identical (I diff the kwargs explicitly); executed notebooks' posterior summaries eyeballed against the committed outputs for gross drift.

### Task T3: the #232 split of `fitter.py` / `sed_model.py` / `parameters.py`

**Executor:** ORCHESTRATOR-LED. Agents receive single-move sub-dispatches only; no agent plans the split.
**Branch:** `refactor/232-module-split`

**Why orchestrator-led:** 3,511-line `fitter.py` with model-keyed caches, JIT identity semantics (`logdensity_fn_2arg` is a *static* argument — function identity is part of the XLA cache key, so moving a function can invalidate persistent caches), and 111 backend references. A cheap agent cannot judge which moves are identity-preserving.

**Target file map (the decision, locked here):**

```
src/tengri/inference/fitter.py          → keeps: Fitter class shell, __init__, run() dispatch
src/tengri/inference/_fit_cache.py      → new: compile_signature/_engine_cache_key/prewarm/save_cache/load_cache/lean policy
src/tengri/inference/_fit_setup.py      → new: data/noise/data_type resolution, likelihood selection, eline/calibration wiring
src/tengri/inference/_fit_compile.py    → new: compile()/_get_or_build_engine and the per-model cache accessors
```

`sed_model.py` and `parameters.py` splits are follow-ups under the same issue, planned after this one lands — one file per PR, never two.

**Procedure (per moved cluster, orchestrator executes or closely reviews):**

- [ ] **Step 1:** Move one cohesive cluster (start with `_fit_cache.py`: the five cache/signature methods) — cut-paste with imports fixed, `fitter.py` keeps thin delegating methods (`def compile_signature(self): return _fit_cache.compile_signature(self)`), so external callers and the 111 backend references see an unchanged surface.
- [ ] **Step 2:** Gate: full fast tier green (`…pytest tests/ -q -n 2`), plus the JIT-identity check: run the same tiny fit twice in one process before and after the move; the second-run wall-time ratio must be unchanged (warm-cache behavior preserved). Paste both ratios.
- [ ] **Step 3:** Commit per cluster: `refactor(inference): extract <cluster> to <file> (delegating shims; no surface change). Refs #232`.
- [ ] **Step 4:** After all clusters: `wc -l src/tengri/inference/fitter.py` in the report — target < 1,500 (from 3,511); a follow-up issue for the remainder if not reached, never a forced squeeze.
